# Practitioner journey

The persistent journey rail has ten stages. Its status and links are derived by
the local server from durable authority; a browser route cannot unlock a stage.
The in-app **Help for this stage** panel restates the relevant purpose, next
step, and boundary without changing state.

| Stage | Practitioner task | Evidence and boundary |
| --- | --- | --- |
| Setup / Workspace | Establish or reopen one startup-selected local workspace and engagement. | Browser input does not select a server path or grant product authority. |
| Destination | Review a controlled profile or draft a workspace-local destination from offline metadata/manual definition. | Activate needed fields, freeze reviewed bytes, then separately approve the exact profile hash. Imported metadata is technical evidence only. |
| Source | Inspect, accept, and profile a ZIP/CSV package. | Structural profiling is sample-free; accepted source evidence remains immutable. |
| Mapping | Route files, bind fields, use supported operations, exact tables, and relationships. | Value-free coverage must be complete; freeze and separately approve the exact mapping. No arbitrary code or fan-out. |
| Validate | Run the approved contract against the accepted source. | Creates immutable local validation evidence, not a source change or external-target result. |
| Compare | Accept a source refresh and compare adjacent revisions. | Compatible reuse is exact; structural drift requires a new mapping draft. Comparison is value-suppressed. |
| Issues | Review findings and create a local remediation pack when needed. | Keys are explicitly selected; offending values require a separate acknowledgement and remain only in the exact ZIP. |
| Decisions | Record bounded local issue decisions for eligible single-entity work. | Decisions and overlays do not rewrite source, validation truth, or approved authority. |
| Reconciliation | Review governed effective local evidence and record a local result approval when eligible. | This is not external-target reconciliation or acceptance. |
| Package | Generate or inspect a deterministic local Readiness Package. | A package is local evidence; it does not transmit data or write to another system. |

## Source-first and destination-first work

The journey permits the available source and destination work to proceed in
either order. Mapping and validation require the exact approved profile and the
accepted source to meet their server-derived gates.

## Revisions and refreshed extracts

Use **Start source refresh** after completed validation when a data owner sends
a revised extract. The product preserves the prior run and any historical local
packages. For compatible structure, it independently replays the prior
approved profile and mapping authority. For drift, it keeps prior authority
intact and requires a new mapping draft and approval.

Adjacent comparisons classify findings as CLOSED, REMAINING, or NEW. When a
declared business key is incomplete, the product documents a private full-row
multiset fallback rather than pretending to have row lineage.

## Multi-entity boundary

Multi-entity work currently ends at read-only First Issues and Compared
Validation. Decisions, Reconciliation, Result Approval, and Package are locked
there by design. This is a current product limit, not a browser-navigation
problem.
